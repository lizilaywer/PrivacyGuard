## 1. 决策摘要

推荐路线：**建立可比较的基线 → 接入现有 OCR 字符框 → 导出重开验证 → PDF 隐藏内容策略 → Word XML 覆盖 → 人工复核与规则批处理增强 → 单独评估依赖升级。**

目标是更少漏脱、更少误遮、便于复核，继续保持离线、轻量、可撤销和可恢复。首轮保留 RapidOCR 3.9.2 + PP-OCRv6 Small，不把算法接入、引擎升级、模型更换、UI 重构绑在同一版本。

“不退步”必须由同样本、同硬件、同依赖、同导出路径的对比和发布阻断规则约束，无法靠承诺或单测数量证明对所有未知文档绝对安全。任何新漏脱、数据损坏、权限绕过或线程崩溃都会阻断发布；未达到目标的功能保持实验关闭或撤回。

优先借鉴工作方法和接口设计，不把外部软件整体嵌入。当前项目已经具备混合 PDF 扫描、手工框选、全文定向遮罩、书签脱敏、页结构编辑、撤销、恢复、报告、Word 双预览和批量替换，不重复建设。

## 5. 阶段安排与完成标准

### S0：冻结基线与建立“不退步”样本（先完成）

任务：

1. 保存源码基准、依赖清单及实际版本、模型哈希、测试结果、硬件/电源模式、启动和扫描耗时、峰值内存、冻结包体积。备份配置和草稿仅在本机受保护目录保存，绝不进 Git。
2. 在独立环境重现 requirements 固定依赖；对当前 venv 做只读记录。两者不一致时先记录/复核，不同时升级多项依赖。
3. 建立建议规模至少 120 份、300 页、1,200 个敏感区域的固定语料；这是目标，不是现成完成量。公开部分全部合成，真实法律样本仅在本机经过授权使用，不上传 GitHub/第三方模型。
4. 开发/调参、验证、最终保留测试集按来源约 60/20/20 分组；同一文书的旋转/模糊变体不能跨组，避免测试泄漏。保留组只用于阶段验收。
5. 每个样本记录：原文/图像、正确字符串和类型、敏感字形区域、允许遮罩边界、应保留文字/图形、文档隐藏内容；危险解析/超大文件另设资源限制用例。

覆盖：纯文字、扫描、混合 PDF；中文/数字/英混排；手机号/证件/姓名/金额；相近字、零宽字符、全半角、跨行、重复文本；小字/倾斜/噪声/印章覆盖；0/90/180/270 度及非零 CropBox；旋转/插入/删除/截去/提取后扫描；加密、取消、错误、损坏模型、导出失败；Word 各部件及跨 run 文本。

验收：基准可复跑，私有样本缺失不会被当成全覆盖；每个已知盲区都有样本或明确待覆盖项。基准先于算法改动。

### S1：同模型字符定位（第一项用户可感知改进）

建议模块：`ocr/char_alignment.py`（解析/索引）、`ocr/hit_geometry.py`（几何校验），扩展既有 `OCRResult/CharInfo`，在现有适配器接入。

实施拆成小提交：

1. 打开当前 RapidOCR 的 `return_word_box` 与 `return_single_char_box`，解析 `word_results`；保持 text/行框/置信度原行为。只做适配与测试，暂不改变遮罩计算。
2. 显式建立“源识别文本偏移 → 字符/词框”映射。标点、空格、合字、漏字、全半角/零宽规范化必须可回到原偏移；对不上时禁用该行字符精确化，不能硬按序号 zip。
3. 需要的命中使用字符框并集及校准的安全边距。多行或不连续命中按片段遮罩，避免一个大框吞掉无关内容。
4. 明确坐标链：识别器返回坐标/内部缩放还原 → 裁剪图像像素 → 图片块原点 → 页面 display 坐标 → 导出 derotation；每一步标注单位，防止二次缩放和二次旋转。
5. 混合页迭代器采用新增适配入口或可选字段保留 chars，不破坏原 `(box,text)` 调用契约；人名回填、手动框选、定向遮罩逐一接入。搜索单独后续处理。
6. 字符框缺失、越界、非有限数、顺序/覆盖不合理、置信度不足时回退当前算法。字符对齐不确定不得产生更小且可能漏字的框；原算法本就无法可靠定位时，明确标为需复核/沿用既有保守失败策略，不把失败当零命中。
7. 先测试开关关闭/开启和影子对比；影子模式只对同一输出比较几何结果，默认不额外运行第二套模型，也不在用户文档中持续双跑。

本轮已有小探针：同一模型离线识别两行合成中文/号码，返回 59 个字符框；5 次交替运行的热态中位耗时约 705/729 ms。只说明能力可接入，不证明字符覆盖更好或真实文书耗时只增 3.4%。内存、长页、竖排尚未在该探针验证。

验收：字符框开关不改变原识别文本；同语料敏感字形覆盖无新增遗漏，误遮显著下降；全部坐标路径及回退路径通过；预览、导出重开与恢复后的遮罩一致。达到第 6 节门槛才成为默认。

### S2：导出验证与安全提交文件（先于更激进增强）

建议模块：`utils/export_validation.py`、`utils/export_transaction.py`；耗时复核由独立 Worker 执行，避免 GUI 失去响应。

流程：源文件不变 → 生成受保护临时输出 → 关闭写入句柄 → 重新打开/认证 → 核验 → 完成时原子替换目标 → 显示最终成功状态。使用目标目录内随机临时文件保证同卷提交；Windows 占用/无权限/磁盘满均安全失败，已有目标不能提前删除。用户取消不覆盖任何最终文件。

验证分层：

- 容器层：可重新打开，页数/尺寸/旋转、期望加密/密码/权限、书签和结构符合目标。
- 目标层：指定敏感位置的可提取文字已移除；保存后的链接/批注/表单目标等依策略核验；Word 指定节点/部件的目标值已替换。
- 视觉层：重渲染抽查或全量检查遮罩区域；“黑色”不是唯一标准，兼容彩色遮罩、替换字和背景。
- 增强层：对导出图片重新 OCR、辅助检测假遮罩，作为额外证据。不能只依赖同一 OCR 自检，系统性漏识别可能同时骗过两次；不能以单纯全文搜不到或原始字节无子串证明彻底净化。

已确认残留或验证异常属于硬失败，不允许静默回退为画矩形后成功。用户主动取消扫描后的部分结果，继续沿用当前明确提示/确认语义；“未检查到的格式”显示覆盖不足，不能冒充验证通过。验证结果区分 `通过（所列检查）/发现残留/未完成/不支持`。

日志只记页码、类型、数量、错误代码，不保存敏感文本/正则/密码；完整原文哈希也不默认放入公开报告，避免低熵原文被猜测。加密输出优先内存解密验证，禁止为了验证另存长期明文副本。

验收：合成“假黑块”、mail 链接残留、加密认证失败、损坏文件、取消、磁盘满、目标锁定、写出中断、提交失败均不会产生假成功/覆盖好文件。

### S3：PDF 隐藏内容的清点与净化策略

建议模块：`utils/pdf_inventory.py`、`utils/pdf_sanitize.py`；在副本上操作，与遮罩几何分离。

先只清点后处理：信息字典、XMP、外部链接/URI/动作、批注、表单及 appearance、附件/关联文件、JavaScript/自动动作、可选图层、隐藏文字、替代文本/结构树、嵌入对象。列表是覆盖计划，不能理解为当前库对每项已具备可靠清除能力。

分级策略：

1. **保持版式导出**：页面内容永久脱敏；明确显示实际处理/保留的隐藏部件。先实现可确认的元数据、链接及附件策略。
2. **净化导出**：明确预览将移除的对象，按策略删除/改写。表单不能简单先 flatten：flatten 会把字段值变成页面内容，必须保证这些内容进入扫描/脱敏及复核。
3. **可选纯图导出**：从已经应用遮罩后的页面渲染并新建文档，禁止复制原文档对象；不沿用原 OCR 层。可搜索层若以后重建，只能从最终已遮像素重新识别。需提醒可选文字、链接、表单、矢量和签名验证能力的损失，以及清晰度/体积变化。

新功能默认不悄悄删用户附件、表单或签名。签名文档修改后可能失去验证有效性，应识别并说明；不承诺保留原数字签名有效。安全净化模式若遇到无法验证的高风险部件，阻止该模式成功发布，提供人工处理建议。

验收：对每类对象设置独立 canary 值，导出重开确认处理结果；保留区域/非目标链接行为可预测；不把 `garbage=2` 当作覆盖所有隐藏对象的净化功能。

### S4：Word 统一 XML 覆盖（分批补盲）

建议模块：`utils/word_parts.py`（受控节点迭代与映射）、`utils/word_inventory.py`（覆盖与风险清点）。继续复用现有 run 级替换，禁止把整个段落重写成一个 run。

顺序：正文/嵌套表格/超链接可见文本 → 全部页眉页脚/脚注/尾注 → 文本框/批注/属性 → 修订删除文本/隐藏文本/字段/内容控件/关系目标 → 嵌入 Office/OLE/图像等无法可靠处理项的明确报告。

扫描、替换和导出验证共用部件 ID、节点路径、run 偏移；mammoth 预览不能作为 Word 内容全集。超链接目标和显示文本分开处理。修订不能盲目全部接受/拒绝，应先识别并确定模式；DOCM/宏/嵌入对象不自动假装支持。

验收：输出 DOCX 的 ZIP/XML 结构和关系有效，Word/LibreOffice 能重开；指定 canary 不留在应处理的 XML 部件；非目标样式、表格、图片和段落内容保持；对未覆盖部件给出报告。不得直接对压缩包的任意字节全局替换。

### S5：人工复核面板与覆盖状态

建议独立 `ui/panels/redaction_review_panel.py`，通过信号定位/确认/拒绝，不把 UI 控件方法塞入 main.py。

- 清单展示页码/位置、类型、来源、置信度或校验说明、待复核状态；默认界面不将原文完整展开，用户定位时可查看上下文。
- “已扫描/空白已检查/未扫描/失败/取消/需复核”区分，尤其覆盖混合页图片块，不能把零命中等同于完成。
- 用户确认、排除、补框和调整都进入撤销/重做与草稿；再次扫描不能悄悄抹掉人工判断。
- 保留规则默认仅本文件、显式作用于选定位置/类型；不得用全局任意子串白名单取消所有同名人/号码的脱敏。冲突时显示，手动遮罩不可被白名单静默撤销。
- 同时保留当前一键扫描流程，以渐进面板补充，不强迫所有用户重新学习工作方式。

验收：既有快捷键、窄窗口/高 DPI/暗色、页面网格、书签面板共存；每个复核操作能撤销/恢复；面板打开不改变扫描结果；关闭面板不丢人工操作。

### S6：规则模板、批量一致性与轻量补盲

1. 带 schema/version 的“卷宗/合同/流水/人事”规则模板，沿用现有自定义规则；预览影响，安全导入校验、大小/数量限制、无任意代码执行；正则执行预算或进程隔离单独评估。
2. 逐文件规则映射：明确匹配优先级/冲突/无匹配时行为；先出计划清单再执行；单文件失败、取消、继续/停止不得串用上一个文件的状态。
3. 一致占位符是可选模式：同一文档/批次中的“张三”可映为“当事人A”；同名不同人/简称关系必须可人工区分，不能自动推断为同一实体。默认使用当前不可逆遮罩/替换，不生成还原字典。
4. 对全半角、OCR 数字间空格、连字符变体进行可追溯匹配；错字近似匹配/地址扩展先作为候选，不直接自动扩大/缩小遮罩。
5. 二维码/条码先评估现有依赖可用性、覆盖和原生包体积；二维码载荷也可能含敏感信息，识别/报告均在本机，不自动访问 URL。人脸/大型 NER 模型留后续可选实验。

验收：模板迁移兼容、旧配置不丢、规则互相不污染；批量取消/失败仍保留已完成结果且报告清楚；一致替换映射不进入结果 ZIP、报告或日志。

### S7：OCR 识别增强和依赖升级，分别试验

- 小字/模糊区域使用同模型局部放大或重叠分块，设页面像素/重试/耗时预算、块间去重和映射；不要整篇固定倍数反复重扫。
- 缓存键至少绑定文档内容/结构版本、页索引、裁剪与旋转、模型哈希、预处理参数；换页/编辑/模型变化使缓存失效。缓存文本和坐标默认会话内存，设置内存上限。
- RapidOCR 3.10.0 在独立环境验证，查默认模型路由、资源收集、离线路径和许可证，不同时改变模型和推理后端；ONNX Runtime 的升级另开提交。
- Medium 可留作独立可选高精度试验，不进默认包；Tiny 不用于提高准确率的默认方案；NER/LLM/云服务不进入本轮默认链路。
- 识别效果提升只有在固定语料的字符错误率/实体漏检改善且资源门槛达标后才能对外宣称。

## 6. 发布门槛：“不退步”的具体含义

以下数值是**待 S0 基线确认的验收目标**，不是本轮实测结果。涉及新增功能的数据必须单列，不能用平均值掩盖困难子集退化。

| 维度 | 必须通过的门槛 | 不通过时处理 |
|---|---|---|
| 功能回归 | 既有有效用例全部通过；数量至少包含原 756 项及新增专项；3 个 skip 理由不扩大；Windows/macOS CI + 原生冻结包自检 | 阻断发布；不改断言迎合新实现 |
| 目标漏脱 | 在已覆盖测试范围内，新增暴露敏感字形/实体为 0；既有高风险已知盲区不增，安全补盲阶段解决的样本必须无残留 | 回退相关功能；已知盲区不能从统计分母删掉 |
| 定位质量 | 按字体/旋转/图像等子集比较敏感字形像素覆盖和完整实体覆盖；不因框更紧漏边；误遮面积中位数目标下降 ≥15%，P95 不恶化 | 没有收益就不切换默认；IoU 仅作辅助 |
| 识别质量 | 同模型字符框接入 text 输出应一致；增强阶段 CER/实体召回不能比基线差；记录误报、整份文档仍含残留的比例 | 拆分分析，不能用识别率平均提升换掉某类证件召回 |
| 资源 | S1 模型/依赖字节不变；同环境热态批量 P50 ≤基线1.10×、P95 ≤1.15×；峰值内存增幅目标≤10%且≤50MB；默认包增幅目标≤1%或5MB中的较小值 | 达不到则优化/实验开关关闭，不宣称轻量不变 |
| 交互/线程 | 后台运行时 GUI 可操作；任务切换/关闭无悬挂线程；取消响应在当前单次推理结束后目标≤1s，不采用强杀线程 | 修正状态/任务边界，不引入不安全 terminate |
| 导出事务 | 导出重开验证、加密和权限检查通过；故障注入下无假成功、无原文件损坏、无提前覆盖旧目标 | 硬阻断 |
| 隐私 | 无新增用户内容网络传输；关闭网络仍可使用；无新增原文明文持久化；报告/日志/结果包无原文映射、密码 | 硬阻断 |
| 兼容/格式 | 当前声明平台逐一验收；Word 布局与样式、PDF 页结构/颜色/替换字/书签及加密不退化 | 对未测平台明确不发布；不能用源码 CI 代替冻结包 |

注：字形覆盖优于仅比较矩形 IoU；整行大框可能召回高但误遮严重，因此覆盖和误遮同时考核。耗时采用同机交替顺序、多次冷/热测，记录输入页数和分辨率；小于噪声的差异不算提升。增强模式允许更慢，但必须独立标示和设预算，不能把成本算进“免费提升”。

### 6.1 手工及端到端矩阵

每阶段按影响面选择，最终发布覆盖：打开/认证 → 扫描/取消/报错 → 预览 → 手动修改 → 撤销/重做 → 旋转/插删/提取截去 → 草稿恢复 → 重置再扫描 → 导出/重开。至少包含：

- 正文有命中、正文零命中仅书签变化、全无变化、删除所有书签。
- 文字/扫描/混合页，旋转页，编辑后的快照而非磁盘旧页序。
- 手动框选/全文遮罩、人名跨页回填、印章签名，不被新字符框路径漏掉。
- PDF 打开/编辑密码、拒绝授权/取消输入、导出加密/改变密码。
- Word 双预览/来源过滤、页眉页脚及新部件；批量规则冲突/错误/取消。
- 不完整扫描提示、损坏资源、存储故障、程序退出/恢复和痕迹清理真实路径保护。

## 7. 发布与回退策略

1. 每阶段一个可独立验收的候选版本，不预先硬排版本号；只有用户可用的改动通过门槛才提升版本。
2. S0 保留基准提交、依赖环境和已验证应用包；模型不原地覆盖。新算法与升级依赖分开，方便识别原因。
3. 开发功能开关默认关闭，单独接受验证后再启用；关闭新功能必须确实走旧路径，防止“有开关但旧路径已删除”。
4. 配置新增字段有默认值，不破坏旧配置；草稿 schema 向后兼容或只读提示，不能无备份原地迁移。含新坐标的草稿应记录版本和源文档指纹。
5. 对实验性模型/依赖，可在本机隔离候选包试用；稳定包及用户文件不受覆盖。安全修复不得以隐藏开关让用户无感退回已知不安全结果。
6. 回退使用独立旧包/隔离检出，开发修复用可审查 revert；不运行历史脚本盲目覆盖当前工作区、配置和用户文档，不强推公共历史。
7. GitHub 发布仍以当前公开分支为父提交，只推已审查源码、合成测试和文档；不带本地私人开发历史/配置/日志/模型缓存/真实卷宗。二进制需实际构建、冻结自检、平台测试、哈希后才上传 Release。
8. 灰度期间的个案问题只保留本机去标识诊断，不新增远程遥测；任何新漏脱/文件损坏立即停止该候选发布，保留复现样本和补测试后再试。
